Scanner mobile et sécurité

Le téléphone dialogue directement avec le PC central sur le Wi-Fi local ; aucun serveur cloud n’est requis.

Pourquoi HTTPS ?

Les navigateurs mobiles demandent un contexte sécurisé pour autoriser l’accès à la caméra. Le scanner est donc servi par HTTPS sur le réseau local. Le certificat est créé et renouvelé par l’application ; le téléphone peut demander de faire confiance à l’autorité locale.

Deux accès distincts

ÉcouteUsageRègle
HTTP, loopback (8765 par défaut)Interface de caisse du PCAccessible seulement depuis la machine centrale.
HTTPS, LAN (8766)Scanner mobileAccès réseau local avec règles spécifiques aux routes et appairage.

Le pare-feu doit rester limité au profil réseau privé et au sous-réseau local. L’application ne requiert pas de redirection de ports depuis Internet ni de DMZ.

Appairage d’un téléphone

  1. Le poste central génère un QR code temporaire.
  2. Le téléphone le scanne sur le même réseau local.
  3. Le serveur échange le code à durée limitée contre un jeton d’appareil.
  4. Le profil du libraire est choisi séparément sur le téléphone.

Les appareils et jetons sont conservés dans data/devices.db, séparément de la base métier. La liste permet d’afficher le profil associé ou de révoquer un appareil.

En cas de problème

  • Vérifier que le PC et le téléphone utilisent le même réseau.
  • Vérifier que le réseau Windows est défini comme privé.
  • Relancer la configuration mobile après changement de réseau ou de PC.
  • Si la caméra ne démarre pas, vérifier que le certificat local est accepté par le navigateur.

La conception détaillée se trouve dans le document source ARCHITECTURE_MOBILE.md ; l’implémentation se trouve dans app/security.py, app/certs.py et app/routers/sync.py.
